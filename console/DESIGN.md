## 1. 骨架

```
┌──────────────┬────────────────────────────────────────────┐
│ 导航栏        │ 顶栏 60px：当前页 h1 + 描述 ｜ 全局控制       │
│ 248px         ├────────────────────────────────────────────┤
│ 观测          │                                            │
│  · 总览       │  main：页面内容（页面自带滚动或工作台式铺满）  │
│  · 回合       │                                            │
│  · 主机       │                                            │
│  · 拓扑       │                                            │
│ 工具          │                                            │
│  · 调试       │                                            │
│  · 设置       │                                            │
│ 状态点/收起    │                                            │
├──────────────┴────────────────────────────────────────────┤
│ 状态栏 30px：连接 · 调用 · 缓存 · 降级 · 在线 · 运行 · 回合 · 版本 │
└───────────────────────────────────────────────────────────┘
```

| 区域 | 尺寸令牌 | 行为 |
|---|---|---|
| 导航栏 `.rail` | `--rail-w` 248px / 折叠 `--rail-w-min` 64px | 品牌标记 + 分组导航（观测 / 工具）+ 收起按钮；折叠态只剩图标，提示由 `Tooltip` 提供 |
| 顶栏 `.header` | `--header-h` 60px | 左侧当前页 `h1`(19px) + 描述；右侧**只放全局操作**：暂停/继续、密度分段、主题切换 |
| 内容 `main` | — | `PageScroll`（整页滚动）或 `PageFlush`（工作台式） |
| 状态栏 `.statusbar` | `--status-h` 30px | 跨两列的实时 KPI；**全站唯一的连接状态**；顶边掠光表示"正在接收"，`reduced-motion` 下真停住 |
| ≤900px | `@media (max-width: 900px)` | 导航栏横置为顶部图标条，不再与内容争宽度 |

**三块外框（导航栏 / 顶栏 / 状态栏）共用画布色，白面内容浮在其上。**
这是编辑风的关键决定：外框自成一套"机壳"，与内容面拉开一层明度差 ——
而不是把每块都刷成一条灰带（那是"通用后台模板"最强的信号）。

用户真实窗口是 **1080×634**（不是 1600×900），纵向很紧，所以顶栏压在 60px、状态栏 30px。
实测 1600×900 下 chrome 只占 **6.7%**（上一版 15.4%）。

**连接状态全站只报一次，位置是底部状态栏。** 这三处曾各报一次（侧栏底部 / 顶栏胶囊 /
状态栏）——同一条信息在一屏里出现三遍，用户实测后明确要求「移除」。
现在顶栏是"操作区"、侧栏只负责导航，读数一律归状态栏；`liveRun` 在跑时那一条会改写成
「装配中」，所以顶栏删掉胶囊也没丢掉"正在装配"这个信号。

**内容不居中留空。** 常规页的每一行栅格都必须吃满可用宽度；曾经设置页挂了一条 820px 的
居中护栏，在用户 1700px 宽的窗口下两侧各空出约 300px，等于把近半屏扔掉。
栅格列数一律写死（`repeat(2, …)`），**不用 `auto-fit`** —— 它在临界宽度会排出「N+1」
这种一眼失衡的版式（总览六档读数曾排成 5+1）。

偏好持久化：`cs-theme` / `cs-density` / `cs-rail`（见 `src/app/prefs.ts`，首帧前写入 `<html>`，避免亮暗闪烁）。
**默认亮色** —— 纸面是这套设计的基准面，暗色是同语义的镜像档。

## 2. 令牌（`src/styles/tokens.css`）

三组选择器，组件里**禁止硬编码色值**：

- `:root` —— 亮色（默认）
- `:root[data-theme="dark"]` —— 暗色，同一套语义换明度方向
- `:root[data-density="compact"]` —— 只收紧内边距与行高

| 组 | 令牌 | 说明 |
|---|---|---|
| 底 | `--bg` `--surface-1..3` `--surface-inset` | 暖中性画布 + 纯白内容面 + 凹槽；不靠阴影拉层次 |
| 线 | `--line` `--line-strong` | 发丝结构线 |
| 字 | `--fg` `--fg-2` `--fg-3` | 主 / 次 / 微 |
| 主操作 | `--ink` `--ink-hover` `--ink-fg` | 实心按钮用**墨**而不是彩色 |
| 品牌 | `--brand` `--brand-fill` `--on-brand` `--brand-soft` `--brand-line` | **唯一强调色（冷蓝）**，只表示品牌 / 在线 / 可交互 |
| 状态 | `--ok` `--warn` `--bad` `--info` `--neutral`（各带 `-soft`） | 绿 / 琥珀 / 红**只表示状态**，绝不兼职强调色 |
| 阶段 | `--stage-1..7` | 单色相明度梯级；`--stage-7` 转琥珀 = 裁剪段 |
| 焦点 | `--ring` `--ring-soft` | 必须真能看见，不是只写在 CSS 里 |
| 尺寸 | `--rail-w` `--rail-w-min` `--header-h` `--status-h` `--panel-pad` `--stack-gap` `--row-h` `--ctl-h` | 外壳与密度 |
| 动效 | `--dur-1..3` `--ease` `--ease-out` | 110 / 170 / 260ms |

**配色**：亮色画布 `#f1f1ef`（暖中性纸面）、内容面 `#ffffff`、强调冷蓝 `#2563eb`；
暗色画布 `#0c0d10`、内容面 `#141519`、强调冷蓝 `#6ea8fe`。

**为什么主操作用墨色而不是蓝色**：一屏里"强调色"只有一个语义，就是**当前所在与可交互**。
主按钮如果也用蓝，它就和"当前选中项"抢同一个信号；用墨色则按钮自己成立，
蓝色留给真正需要指路的地方（当前页 / 选中行 / 焦点环 / 正在接收）。

**对比度是反推出来的，不是挑出来的**。`qa:layout` 逐叶节点实测，全部 ≥4.5:1。要点：

- `--fg-3` 承载 10–11px 微标签，属**小字号**，必须按 4.5:1（不是 3:1）选色，
  且要压在最深的那个底上（`--surface-3`）也达标 —— 上一版 3465 条 FAIL 的根因就是这里。
- 语义色（`--ok` / `--bad` …）按「压在 10% 自身上」核算；亮色下它们已是深色，
  实心徽章的文字必须是白；暗色下反过来，靠 `:root[data-theme="dark"] .tone-*` 翻。
- `--surface-3`（悬停底）必须**明显比画布深**，否则导轨悬停、表格行悬停会看不见。

**字体**：UI `Inter`（可变字体，wght 100–900）+ 系统 CJK 栈（PingFang SC / HarmonyOS Sans SC /
Microsoft YaHei UI）；数值 `JetBrains Mono` + `tabular-nums`（纵向比对必需）。

两个字体族**本地自托管**（`src/assets/fonts`，见 `styles/fonts.css`），**不连任何 CDN**：
都是可变字体，一个 latin 子集 woff2 覆盖全部字重（合计约 80 KB）。

为什么不走 Google Fonts：控制台是**本机工具**，断网时也应当长成设计的样子 ——
走 CDN 时断网只会静默回落系统字体，观感与设计稿不一致，而控制台里看不出任何异常。
自托管之后 `viz-server` 的 CSP 也随之收紧成 `font-src 'self'`，页面不再请求任何外部源。

**CJK 不下载字体**：`@font-face` 带 `unicode-range`（latin），中文码位根本不匹配这两个 face，
浏览器直接去系统栈 —— 不为 CJK 付那几百 KB。

**密度**：`comfortable`（默认）/ `compact`。紧凑档只改 `--panel-pad` `--stack-gap`
`--row-pad-y` `--row-h` `--ctl-h`，**不碰字号**——字号一动，整个对比度矩阵就要重算。

## 3. 样式分层（`src/main.tsx` 按序引入）

| 文件 | 职责 |
|---|---|
| `styles/fonts.css` | 自托管 `@font-face` |
| `styles/tokens.css` | 令牌，唯一色值来源 |
| `styles/base.css` | 重置、排版基线、`:focus-visible`、滚动条、工具类。**不含组件样式** |
| `styles/ui.css` | 原语样式（按钮 / 徽章 / 面板 / 表单 / 表格 / 提示 / 抽屉 / 通知…） |
| `styles/app.css` | 外壳与页面框架（导航栏 / 顶栏 / 状态栏 / `.page` / `.split`） |
| `styles/charts.css` | 图表 |
| `pages/*.css` | 各页面专属版式 |

**导入顺序即层叠顺序**：`App` 必须**晚于**样式导入。ESM 按导入声明顺序求值，
App 先导入时各页面 css 会排到 `ui.css` **之前**，于是 `.st-select` 这类
「同名同特异性」的页面规则被 `.select` 静默压掉（踩过：工具条三个下拉撑满整行）。

**原语**（`src/ui`）：`Button` `IconButton` `Badge` `Dot` `Chip` `Panel`(+Head/Body)
`Stack` `Row` `Field` `TextInput` `Select` `Textarea` `Segmented` `Tooltip`
`DataTable` `Stat` `Toolbar` `Spinner` `Empty` `Alert` `Code` `Toast` `Drawer`。

**图表**（`src/charts`）：`Sparkline` `AreaChart` `StageRail`——全部手写 SVG，不引图表库。

**运行时依赖只有 4 个**（`lucide-react` / `react` / `react-dom` / `react-router-dom`）——
不要再引入 CSS 框架或图表库。

## 5. 动效

只动 `transform` 与 `opacity`；时长走 `--dur-*`（110–260ms）。
**全部动效在 `prefers-reduced-motion: reduce` 下关闭**——且由体检脚本**实测计算样式**守着
（写在 CSS 里不等于生效：被后面的规则覆盖、选择器写错都会静默失效）。

## 6. 版式体检（改完 CSS 必跑）

**缩略图会骗人。** 一个 65px 的徽标被挤到 21px、某个容器把内容吃掉 188px——
这类问题在截图、在 typecheck、在单测、在控制台日志里**都看不出来**。所以版式问题一律用数字查，
工具是项目常驻脚本（`console/tools/`），不是一次性临时代码：

| 命令 | 做什么 |
|---|---|
| `npm --prefix console run qa:classes` | **静态**类名审计（CSS 定义 ↔ TSX 引用求差集）。不需浏览器，进 CI |
| `npm --prefix console run qa:layout` | **浏览器**体检（需先起服务：`node tools/viz-server.cjs --port 7331`） |
| `npm --prefix console run qa` | 两者都跑 |

`qa:layout` 自动灌 46 轮有梯度的真实遥测（走公开的 `/api/turn`），然后扫
**2 主题 × 2 密度 × 10 档宽度**（含每个断点 ±1）× 8 路由，判定：

> 灌数据是**限速**的（每 20 条歇 1 秒，等限流窗口翻页后才开始扫描）。
> 服务端有按 IP 的 30 次/秒限流，一口气 POST 46 轮会当场把额度用光，
> 紧接着第一格体检的 `/api/snapshot` 就吃 429 —— 而 429 在浏览器里是一条 console error，
> 会被记成"页面异常"。**实测：会灌数据的那一轮 FAIL 18，跳过的下一轮 FAIL 0。**

| 级别 | 条件 |
|---|---|
| FAIL | 文档横向溢出 / 内容被容器吃掉 / 对比度不足 / 页面异常 / 焦点圈不可见 |
| WARN | 省略号截断（分组统计；带 `title` 的归"可接受"，读不到全串/命中区 <20px 的归"可处理"） |

浏览器用 **playwright-core + 系统 Edge**（`channel: "msedge"`），不下载 Chromium。

### 本轮实测基线（1600×900）

```
qa:classes  CSS 定义 315 · 类名语境引用 296 —— 用了但没定义 0 · 定义了没人用 0
qa:layout   FAIL 0 · WARN 70（可处理 0 · 全部为自带 title 的有意截断）
            reduced-motion 实测：.stage>* = none · .rail-dash = none
            chrome 占视口：6.7%（main 810px）
```

**判据是 `FAIL 0` 与「可处理 0」**；`WARN` 的绝对条数随那 46 轮灌进去的数据而变，
不必对数字。

### 体检本身也要被验证（反向测试）

一个只输出 0 的检查，可能是"什么都没测"。所以对关键判据做过反向验证：

- **焦点圈**：注入 `:focus-visible { outline: none }` 后，判据必须在样本上报错。
  ⇒ 所以**任何地方都不要给可聚焦元素写 `outline: none`**（输入框的 `:focus` 只加
  边框色与 `box-shadow` 光晕，不遮蔽 `:focus-visible` 的轮廓）。
- **类名审计**：只扫 `className=` 会把 `{ ok: "led-ok" }` 这类映射拼出来的类全报成孤儿；
  补上"所有字符串字面量"这一遍之后才只剩真死代码。
- **颜色解析**：`color-mix()` 的计算结果是 `oklab(...)` / `color(srgb ...)`，不是 `rgb()`。
  只认 `rgba()` 会把深色段落上的深色文字误报成 1.04:1。

## 7. 无障碍

- 对比度由 `qa:layout` 逐叶节点实测，**全部 ≥ 4.5:1**（大字号 ≥ 3:1）。
- `:focus-visible` 走 `--ring`；`.tip::after` 收起时用 `display: none`——
  绝对定位的伪元素仍会被算进祖先 `scrollWidth`，看不见的提示会把整个外壳撑出横向溢出。
- 颜色**不是唯一**指示：每个状态点旁边永远有文字。
- 语义地标：`nav` / `header` / `main` / `footer` / `section`，唯一 `h1`。
